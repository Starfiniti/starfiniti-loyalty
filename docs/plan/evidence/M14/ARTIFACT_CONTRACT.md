# M14 Production Artifact Contract

This contract defines the minimized evidence required before `M14-MANAGED-BILLING` can close. The executable authority is `scripts/validate-managed-billing-canary-evidence.mjs`; this document explains the operator-facing shape.

Every artifact uses `starfiniti.managed-billing-canary-artifact.v1`, names one exact artifact ID, binds the candidate commit and mandatory checks, records an exact UTC observation time, reports `verified`, and is stored as a unique regular JSON file of at most 256 KiB under `docs/plan/evidence/M14/production/`. The manifest binds its exact SHA-256 digest. Evidence must remain minimized and must not contain credentials, provider resource IDs, payment/contact data, raw webhooks, card-like values, or reusable authority.

## Required detail contracts

| Artifact                | Required semantic evidence                                                                                                                                                                                                                                                                                                                        |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `read_only_baseline`    | Exact public HTTP/DNS results, distinct running application/database VMs, `self_hosted`, provider unconfigured, read-only scope, and zero mutations. Values must match the manifest baseline.                                                                                                                                                     |
| `release_inventory`     | Approved release and PR/commit identity; distinct dashboard, worker, connector, migration, configuration, and authority-mount inventory digests; `self_hosted`/provider-disabled pre-canary state; zero managed tenants and migration difference.                                                                                                 |
| `approval_record`       | Exact five approvals with individual UTC times and unique source digests, final release, and exact digest bindings to every other production artifact.                                                                                                                                                                                            |
| `recovery_point`        | Creation/verification times; distinct base-backup, WAL, configuration, and restore-evidence digests; successful restore evidence; measured RPO at most 60 seconds; zero production mutations.                                                                                                                                                     |
| `production_baseline`   | Exact capture time and snapshot digest; complete source coverage; zero managed tenants, provider requests, ambiguity, checkout blocks, ledger difference, or mutation before canary enablement.                                                                                                                                                   |
| `canary_journal`        | Bounded start/end with at least one complete interval per started UTC hour; exactly one pilot tenant; zero non-canary enablement and self-hosted provider requests; three isolated authority mounts; exact migration registration; complete source coverage; one unique digest-bound zero-difference assertion for every journal-supported check. |
| `reconciliation_report` | Complete source coverage and bounded provider convergence; zero ambiguity or Critical/High findings; one unique digest-bound zero-difference assertion for every reconciliation-supported check.                                                                                                                                                  |
| `rollback_report`       | Exact measured duration, provider operations disabled, protected paths and checkout available, self-hosted no-call preserved, zero ambiguity/ledger difference, source digest, and exact per-check zero-difference assertions.                                                                                                                    |
| `observation_report`    | A measured period of at least 24 hours covering the canary; complete source coverage; zero self-hosted provider requests, checkout blocks, protected-path differences, ambiguity, or Critical/High findings; source digest and exact per-check zero-difference assertions.                                                                        |

## Chronology and closure

Every prerequisite approval plus the release inventory, verified recovery point, and production baseline must precede canary start. Reconciliation and rollback evidence must follow canary end. The observation period must begin no later than canary start and end no earlier than canary end. The final approval record must follow reconciliation, rollback, and observation, and the manifest observation time must follow that approval.

All artifact paths and digests must be distinct. A valid digest over an empty, renamed, incomplete, nonzero-difference, temporally impossible, or differently approved evidence body fails closed. Pending artifacts must keep both path and digest `null`.
